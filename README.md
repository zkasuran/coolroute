# Cool Route Planner

A heat-aware routing and scheduling agent for people who work, ride or walk
outdoors in hot cities. Ask it for the coolest walking route between two points
or the coolest time-of-day window for an outdoor task. It answers from
hyperlocal 2m-above-ground temperature rather than a generic city forecast.

The agent is an LLM that calls the FortyGuard Temperature API as its tools. It
grounds every number in the API (heat index, wet-bulb, shade), leads with a
recommendation then attaches a heat-risk band with a safety note.

Built for FortyGuard Hackathon'26, AI Agents track.

## Why it matters

A city-level forecast says "42 C in Delhi today." That does not tell a delivery
rider which of three roads bakes hardest at 2pm or that the 7am window is 9 C
cooler in felt terms. Heat is hyperlocal and it is a health risk: shade, surface
and humidity move the felt temperature by more than the map does. This agent
turns FortyGuard's hyperlocal data into a single, defensible decision for an
outdoor worker: go now or wait, take this street or that one.

## What it does

- **Coolest time window** ranks candidate start hours by average felt
  temperature over a task window and names the coolest slot.
- **Coolest route** samples points along each candidate route, scores heat
  exposure and shade then picks the coolest path with the distance trade-off.
- **Point conditions / area snapshot / street shade** back the two planners and
  are exposed to the agent as tools.

Felt temperature uses the NWS heat-index (Rothfusz) regression and wet-bulb uses
Stull (2011); risk bands follow the NWS heat-index categories. See
`docs/fortyguard-api-usage.md`.

## Quickstart

```bash
pip install -r requirements.txt
cp .env.example .env            # fill in the reasoning-model values to use `ask`

# deterministic, offline, no keys needed (mock backend):
PYTHONPATH=src python -m coolroute demo
PYTHONPATH=src python -m coolroute coolest-route
PYTHONPATH=src python -m coolroute coolest-time

# the full agent (needs a reasoning model configured in .env):
PYTHONPATH=src python -m coolroute ask "Coolest 2-hour window to work outdoors in Delhi on 2024-07-15?"

# web UI:
PYTHONPATH=src uvicorn web.app:app --port 8000
```

## Deploy

The web UI ships with a `Dockerfile` and reads all config from the environment,
so it runs on any container host with no secrets in the image. It defaults to the
mock backend, so a public demo needs no FortyGuard key.

```bash
docker build -t coolroute .
docker run --rm -p 8000:8000 -e COOLROUTE_WEB_KEY=$(openssl rand -hex 16) coolroute
```

See `docs/deploy.md` for the runtime variables, the security notes and how to
point it at the live API once the key lands.

## The mock backend (why the app runs today)

The FortyGuard API key is issued by email after a screened registration, so this
project ships with a deterministic **mock** backend so the whole agent runs
offline now. The mock returns data in the documented FortyGuard response shapes,
generated by a small physical heat model (diurnal curve, urban-heat-island
offset, humidity from dewpoint, shade). It is not real data and never pretends to
be: every mock response is tagged `"source": "mock"`, the CLI and web UI print
the backend, the agent says so in its answer.

Going live is one line of config once the key lands:

```bash
# in .env
FORTYGUARD_BACKEND=live
FORTYGUARD_API_KEY=<the emailed key>
```

No code above the adapter changes. The live client (`src/coolroute/fortyguard/
live.py`) already implements the documented contract: POST with the key in the
`api-key` header plus the submit-then-poll `status` flow. Its request shapes are
covered by a contract test that runs without a real key.

## Reasoning model

The agent uses a top-tier OpenAI model reached over an OpenAI-compatible
endpoint. Host, key and model id all come from the environment (`OPENAI_API_KEY`,
`OPENAI_BASE_URL`, `OPENAI_MODEL`); nothing is hard-coded. The config loads `.env`
with override so a stale shell variable cannot redirect the agent.

## Layout

```
src/coolroute/
  config.py            settings, loads .env with override
  fortyguard/          the API adapter
    base.py            contract, constants, error type, window validation
    heatmodel.py       deterministic heat physics for the mock
    mock.py            offline backend, documented shapes, tagged "mock"
    live.py            real HTTP backend (api-key header, submit+poll)
  geo.py               distances, route sampling, GeoJSON AOI
  planner.py           coolest-hour / coolest-route analyses over the adapter
  tools.py             OpenAI tool schemas + dispatcher
  agent.py             the tool-calling loop
  llm.py               reasoning-model client factory
  cli.py               command line
web/                   FastAPI demo UI
tests/                 35 tests, all offline
scripts/prove_gateway.py   proves the tool-calling round trip
```

## Security note

The demo web server (`web/app.py`) has **no authentication by default**. It only
reads heat data and performs no writes, so the blast radius is low, but do not
expose it publicly as-is. Set `COOLROUTE_WEB_KEY` to require an `x-api-key`
header on the planning endpoints; when it is unset the server logs a warning and
runs open, which is intended only for a local demo.

## Tests

```bash
python -m pytest        # 35 passed, fully offline
```

Covers the heat model, the mock backend (shapes, determinism, the 2019 floor and
12-hour forecast cap), geometry, the planners, the tool layer, the agent loop
(with a scripted fake model, no network) and the live client's request contract
(with a mocked HTTP transport, no real key).
